# Fantasy Projection Engine

Weekly full-PPR fantasy football projections that try to beat a simple average by modeling situational effects, and that publicly grade themselves every week.

## Plain-English map of the project

| Folder / file | What it is |
|---|---|
| `CLAUDE.md` | The project's rulebook (goals, rigor rules, roadmap). |
| `DECISIONS.md` | Every modeling choice and why we made it. |
| `src/fantasy_projection_engine/` | The actual code. |
| `  data.py` | Downloads free NFL data (nflverse) and saves it locally. |
| `  scoring.py` | Turns box-score stats into full-PPR points. |
| `  quality.py` | Data-quality checks (duplicates, missing weeks, scoring matches, …). |
| `  player_games.py` | Adds games where a player was on the field but recorded no stats (0 points), using snap counts. |
| `  baseline.py` | The naive baseline: weighted average of a player's past games. |
| `  team_context.py` | Team totals per game (targets, carries, attempts) for share × team-volume modeling. |
| `  betting.py` | Betting lines → each team's implied points and spread; team-volume regression. |
| `  opp_eff.py` | Opportunity × efficiency model: volume × points-per-touch, with shrinkage. |
| `  tuning.py` | Picks model settings using only the seasons it's given. |
| `  calibration.py` | Turns the average projection into a median, floor and ceiling. |
| `  predict.py` | **The one function that makes projections**: median, floor, ceiling and a step-by-step "why" for every player. |
| `  metrics.py` | Error measures (MAE, RMSE) and the paired significance test. |
| `scripts/run_phase1.py` | Runs everything above and writes a report. |
| `scripts/exp_*.py` | Experiments testing whether a feature earns its place. |
| `paper/` | Paper-ready results tables, each regenerated by a script. |
| `FEATURE_LOG.md` | Every feature tried, with its error change, kept or rejected. |
| `tests/` | Automatic checks that the math is right and nothing peeks at the future. |
| `reports/phase1_report.md` | Latest results. |
| `data/` | Downloaded data (not saved to git; re-download any time). |

## How to run it (Terminal)

```bash
uv run python scripts/run_phase1.py --refresh   # download data + run everything
uv run python scripts/run_phase1.py             # rerun using already-downloaded data
uv run python scripts/check_predict.py          # check the prediction function + show example explanations
uv run pytest                                   # run the tests
```

## Current status
Phase 1 (Foundation) complete. Phase 2 in progress.
- Step 1 done: snap-count zero games (a significant improvement; see `FEATURE_LOG.md`).
- Step 2: opportunity × efficiency model (`opp_eff.py`) with shrinkage on both volume and efficiency, tuned on fantasy-relevant players. **It beats the baseline on the Big-60 by about 0.06 pts MAE (p ≈ 0.003), out-of-sample 2020–2023.** Paper table: `paper/results_shrinkage_ablation.md`.
- Step 3: team context (share × team volume) on its own: no Big-60 gain.
- Step 4: **betting lines** feed team volume. v4 beat the baseline on the Big-60 by 0.119 pts MAE (p < 0.001), out-of-sample 2020–2023. The lines' own contribution is −0.045 (p < 0.001), confirmed by a placebo test. Paper: `paper/results_betting_lines.md`.
- Step 5: **betting lines for efficiency**: in games the market expects to be high-scoring, each target, carry and pass attempt is worth more (≈ +1.1% to +1.9% per extra implied point). **Current model (v5) beats the baseline on the Big-60 by 0.188 pts MAE (p < 0.001), out-of-sample 2020–2023.** Paper: `paper/results_eff_lines.md`.
- **2024 validation (one-time, true holdout): passed.** The frozen v5 model beats the baseline on the Big-60 by 0.158 pts MAE (6.506 → 6.349, p = 0.002) and wins 15 of 18 weeks head-to-head on the baseline's own top 60. Paper: `paper/results_validation_2024.md`.
- Tried and **rejected**: a week-of-season adjustment (early/mid/late). It didn't lower error, so v5 stays current. Paper: `paper/results_week_phase.md`.
- Tried and **rejected**: boosting teammates' shares when a player is ruled Out/Doubtful (vacated opportunity). The reallocation is real (about half of a missing player's share goes to same-position teammates), but it didn't lower Big-60 error. Paper: `paper/results_vacated.md`.
- Step 6: **median calibration**. The Big-60 grades average error, which rewards projecting a player's *typical* (median) score, not his average score. A final per-position adjustment fitted by median regression converts one into the other. The final version (**v8m, current model**) is one percentage per position: a player's typical score is about 87% of his average projection for RBs, 92–93% for WRs and TEs, and about 102% for QBs. **It beats the baseline on the Big-60 by 0.249 pts MAE and on all players by 0.136, out-of-sample 2020–2023.** Paper: `paper/results_median_cal_mult.md`.
- Step 7: **floor and ceiling** (10th and 90th percentiles). For top players, 80.8% of real scores land between floor and ceiling (target 80%). A typical top WR projected for a 14-point median has a floor near 5 and a ceiling near 27; fantasy football is that noisy. The first version's floors were far too high for backups (51% coverage). The current version (**v10**) lets the range depend on projection level and on each player's own boom-or-bust history: **82.5% coverage for top players, 79.0% for all players.** Paper: `paper/results_intervals_v10.md`.
- Step 8: **explanations**. One function now makes every projection and shows how it was built, e.g. *recent average 19.9 → +0.7 role & efficiency → −0.8 betting lines: team volume → … → median 18.2 (floor 4.6, ceiling 34.5)*. The steps add up exactly. A check on real data confirms no projection uses later games. Examples: `paper/check_predict.md`.
- Tried and **not adopted**: a Week 1 adjustment. Top players do score below their projection in openers (especially RBs and TEs), and the adjustment moved the right way, but with only four openers to test on, the gain (−0.05 pts) wasn't statistically significant. Player-specific Week 1 effects made things worse. Paper: `paper/results_week1.md`.
- Tried and **rejected**: a prime-time adjustment (night games), including player "prime-time splits". Betting lines already price prime-time scoring; top players beat their median 50.2% of the time in prime time vs 50.8% otherwise. A placebo on random games exposed a fitting bug that also affected the Week 1 test (see `DECISIONS.md`). Paper: `paper/results_prime_time.md`.
- Baseline MAE on development seasons 2019–2023, Big-60-style pool, complete data: **6.76 points per player**. That's the number to beat.
